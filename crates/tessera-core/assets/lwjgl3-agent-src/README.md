# lwjgl3-agent

Makes a **vanilla** Minecraft run on **LWJGL 3.4.3** instead of the LWJGL 2.9.4
Mojang ships, without a mod loader and without a mod. Verified against 1.8.9 on
Java 28 EA (that is the version the launcher locks vanilla to).

This is not Vulkan. 1.8.9 draws with the GL fixed-function pipeline (`glBegin`,
display lists, `glMatrixMode`), and Vulkan has no such thing; the only way to
"run it on Vulkan" without rewriting the renderer is a GL-over-Vulkan
translation, which is what Mesa's zink does. Install zink if you want the game
on Vulkan; this agent gives it the modern windowing/input/audio library.

## What it does

Two halves, both in this one jar:

1. **The shim** (`org/lwjgl/**`): LWJGL 2's API, implemented on GLFW 3 and
   LWJGL 3. Only the surface 1.8.9 actually touches is implemented — that set was
   derived by scanning the game's and its libraries' constant pools, so a missing
   method is a `NoSuchMethodError` in testing, not a silent no-op.
   The `org/lwjgl/util/vector` classes are LWJGL 2's own (BSD-3-Clause).
2. **The agent** (`TesseraLwjgl3Agent`): rewrites the call sites where LWJGL 3
   spells a method differently, e.g. `GL11.glGetInteger(int, IntBuffer)` →
   `glGetIntegerv`, `GL20.glUniform4(int, FloatBuffer)` → `glUniform4fv`,
   `AL10.alListener` → `alListenerfv`. The 33 renames and 5 bridges in the
   source were generated by comparing the game's references against the 3.4.3
   jars; the bridges cover what has no same-name equivalent at all
   (`GL20.glShaderSource(int, ByteBuffer)`, `AL.create/destroy/isCreated`).

The agent appends its own jar to the system class loader search, so the shim
classes are visible to the game without any classpath surgery for them.

`TESSERA_LWJGL3_PROBE=1` creates a hidden GL context before the game starts. It
exists to debug a crash that happens before `Display.create`: the game's crash
report calls `glGetString`, and without a context the JVM aborts before printing
the real exception.

## Build

Needs a JDK and the LWJGL 3.4.3 artifacts. The modules used are
`lwjgl`, `lwjgl-glfw`, `lwjgl-opengl`, `lwjgl-openal` (plus their
`-natives-<platform>` jars at runtime) and `asm` 9.7.1 (bundled into the jar).

```sh
# 1. the shim + agent classes
javac -cp "$LWJGL_JARS:$ASM_JAR" -d build $(find . -name '*.java')
# 2. ASM goes into the jar so the agent needs no extra file
cd build && unzip -q "$ASM_JAR" 'org/objectweb/asm/*'
# 3. manifest
printf 'Premain-Class: TesseraLwjgl3Agent\n' > META-INF/MANIFEST.MF
jar cfm ../../lwjgl3-agent.jar META-INF/MANIFEST.MF .
```

## Run

The game's classpath must have the LWJGL 2 jars removed and the LWJGL 3.4.3
jars added; everything else stays as installed.

```sh
java -javaagent:lwjgl3-agent.jar \
     --enable-native-access=ALL-UNNAMED \
     -cp "<lwjgl3 jars>:<game libraries>:<game jar>" \
     net.minecraft.client.main.Main --username Dev --version 1.8.9 ...
```

What a successful start looks like:

```
LWJGL Version: 2.9.4 (LWJGL3 shim)      <- our shim answering the version call
[tessera-lwjgl3] Display.create ok 854x480
OpenAL initialized.
Sound engine started
Created: 512x512 textures-atlas
```

## Known gaps

* Only 1.8.9 has been run. The API surface is derived from this version, so
  another version will report its own missing methods as `NoSuchMethodError`.
* Key mapping covers letters, digits, F1–F15, arrows, modifiers, punctuation and
  the numpad; anything else maps to `KEY_NONE` (`getKeyName` still works).
* `Mouse.setGrabbed(true)` uses `GLFW_CURSOR_DISABLED`, so deltas are the
  driver's; LWJGL 2 recentred the cursor itself. Behaviour is equivalent for
  camera look, but a driver that reports jumps will show them.
* No `Pbuffer`, no `Drawable`, no `Cursor`; the game does not use them.
